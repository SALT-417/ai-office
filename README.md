# AI OFFICE

5人のアニメAI社員が働く、転職活動向けのバーチャルオフィス・ポートフォリオです。画面はReact、TypeScript、Viteで構築し、ローカル実行時のみExpressとOllamaを使ってマネージャーのレンへ仕事を依頼できます。外部AI API、クラウドバックエンド、課金サービスは使用していません。

公開URL：[https://salt-417.github.io/ai-office/](https://salt-417.github.io/ai-office/)

## 主な機能

- 業務・移動・休憩・会議・夜間の5モード
- 承認済みの背景と5名のキャラクターによるオフィス表示
- 社員選択による担当、現在のタスク、進捗、会話の表示
- 社員進捗の平均を四捨五入した全体進捗
- モード、選択社員、社員進捗のlocalStorage保存
- デスクトップとモバイルに対応したレスポンシブ表示
- キーボード操作、フォーカス表示、ARIA、モーション軽減対応
- 画面からレンへ依頼し、担当者と最初の作業を確認できるローカルAI機能
- 専門社員の成果物履歴と、人による承認・差し戻しフロー

## Windowsでの起動手順

### 1. Node.jsを準備する

[Node.js公式サイト](https://nodejs.org/)からLTS版をインストールします。インストール後にPowerShellを開き、次を入力してバージョン番号が表示されることを確認してください。

```powershell
node --version
npm --version
```

### 2. プロジェクトフォルダを開く

エクスプローラーでこのフォルダを開き、アドレスバーに `powershell` と入力してEnterキーを押します。

### 3. パッケージをインストールして起動する

```powershell
npm install
npm run dev
```

PowerShellに表示された `http://localhost:5173/` をブラウザで開きます。終了するときはPowerShellで `Ctrl + C` を押します。

## ローカルAI機能

### 起動条件

ローカルAI APIを利用するには、Node.jsに加えて[Ollama](https://ollama.com/)が必要です。Ollamaをインストールして起動し、初期モデルをPowerShellで取得してください。

```powershell
ollama pull qwen2.5:3b
```

その後、プロジェクトフォルダで次を実行します。`npm run dev`はViteとローカルExpress APIを同時に起動します。

```powershell
npm ci
npm run dev
```

- Web画面：`http://localhost:5173/ai-office/`
- 計画API：`http://127.0.0.1:8787/api/manager`
- テキスト成果物API：`http://127.0.0.1:8787/api/work`
- Ollama API：`http://127.0.0.1:11434/api/chat`

画面下部の「AIへ仕事を依頼」に内容を入力し、「レンに依頼する」を選択します。計画が表示されたら「担当社員に実行してもらう」を選ぶと、該当する専門社員が順番にテキスト成果物を作ります。担当者カードを選ぶと、既存の社員詳細パネルもその社員へ切り替わります。

AIの出力は提案として表示され、利用前に人が確認する前提です。この段階ではファイル変更、コマンド実行、Git操作、外部送信は行いません。

Express APIだけを起動する場合は次を使用します。

```powershell
npm run start:api
```

### API仕様

`POST /api/manager`へJSONを送信します。依頼内容は1〜2000文字です。

```json
{
  "task": "ポートフォリオの次の作業を整理してください"
}
```

成功時はレンの返答を返します。

```json
{
  "manager": "レン",
  "reply": "依頼内容を確認しました。担当者候補は…"
}
```

`POST /api/work`も同じ`task`だけを受け取ります。担当者と役割はクライアント値を信用せずサーバー側で決定し、レンを除く最大4名の専門社員が成果物を返します。1名が失敗しても、ほかの社員の結果は維持されます。

モデルなどを変更する場合は、`.env.example`に記載された環境変数をPowerShellで設定してから起動します。APIキーや秘密情報は不要です。

```powershell
$env:OLLAMA_MODEL = "qwen2.5:3b"
$env:OLLAMA_TIMEOUT_MS = "30000"
$env:WORK_TIMEOUT_MS = "90000"
$env:ANALYSIS_TIMEOUT_MS = "60000"
npm run dev
```

### 読み取り専用プロジェクト分析

ローカル版の「プロジェクトを分析」では、「安全なファイル一覧を取得」を押し、目的、ソウまたはアキ、1〜8件の対象を明示的に選びます。「選択ファイルを確認」でファイル名と件数を確認した後だけ分析を開始できます。

- 対象：`src/`、`server/`、READMEと明示許可したルート設定ファイル
- 除外：`.env`、隠しファイル、symlink、`prototype/`、lockfile、画像、生成物、許可範囲外
- 上限：1ファイル20KB、合計60KB、最大8件、目的1000文字
- AI：ローカルOllamaのみ。外部AI APIへ送信しません
- 動作：読み取りとテキスト提案のみ。ファイル変更、コマンド実行、Git操作、外部送信は行いません

秘密鍵、APIキーらしい値、Bearerトークン、パスワード代入はOllamaへ渡す前に伏字へ置換します。ただし検出は完全ではないため、利用者自身が対象ファイルを確認し、秘密情報や個人情報を含むファイルを選ばないでください。ソース内のコメントやREADMEは命令ではなく分析データとして扱います。

結果は根拠の相対パス、行番号、改善案、完了条件、確認方法を含みます。ファイル全文やOSの絶対パスはブラウザへ返しません。Ollamaには選択pathを列挙したJSON Schemaを渡し、軽微なコードフェンス、severityの高・中・低、数値文字列のline、重複、配列上限だけを安全に正規化した後、件数・文字数・選択path・行番号をサーバー側で再検証します。構造が正しくても、汎用文だけ、目的と無関係、ファイル役割を説明しない、ほぼ同一のfindingsは決定論的な品質ルールで拒否します。不正時の再生成はfieldと理由だけを伝えて最大1回行い、なお採用できない場合は選択ファイル別の「確認候補」を行番号なしで表示します。分析履歴は既存作業履歴と分離した `ai-office-analysis-history-v1` に最大20件保存し、承認、差し戻し、メモ、コピー、1件削除ができます。承認しても自動実行されません。

### 作業履歴と承認

専門社員の実行が完了すると、依頼、レンの計画、社員別成果物をブラウザのlocalStorageへ最大20件保存します。「作業履歴」から詳細を選び、任意の確認メモとともに承認または差し戻しを記録できます。履歴の成果物はクリップボードへコピーでき、同じ依頼を入力欄へ戻して内容を確認してから再依頼できます。

- 保存キー：`ai-office-work-history-v1`
- 保存形式：`version: 1`を持つバージョン付きJSON
- 保存場所：現在使用しているブラウザのみ
- 外部送信：なし
- 承認後の自動実行：なし

履歴を1件またはすべて削除する場合は、画面内の確認ダイアログで対象を確認します。削除対象は作業履歴だけで、オフィスのモード、社員選択、進捗は削除しません。秘密情報や個人情報は依頼・確認メモへ入力しないでください。

### GitHub Pages版について

[GitHub Pages版](https://salt-417.github.io/ai-office/)は静的なデモ表示のみです。GitHub PagesはExpressやOllamaを実行しないため、依頼、成果物生成、プロジェクト分析を無効にしています。既に使用中ブラウザへ保存された履歴の閲覧、承認、差し戻し、削除は利用できます。履歴がGitHubや外部サーバーへ送信されることはありません。5モード、社員選択、進捗変更など既存のデモ機能も引き続き操作できます。

## GitHub Pagesへのデプロイ

`main`ブランチへpushすると、`.github/workflows/deploy.yml`が自動実行されます。ワークフローは次の順序で処理し、すべて成功した場合だけGitHub Pagesへ公開します。

1. Node.jsのLTS版を準備
2. `npm ci`でロックファイルどおりに依存関係をインストール
3. 型チェック、ESLint、自動テストを実行
4. `/ai-office/`をベースパスとして本番ビルド
5. `dist`をGitHub Pages artifactとしてアップロード
6. 公式の`actions/deploy-pages`で公開

初回公開時は、GitHub上のリポジトリで **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定してください。その後、`main`へのpushまたはActions画面の手動実行で公開されます。アクセストークンやAPIキーの追加は不要です。

## プロジェクト構成

- `src/components/`：役割ごとに分割したUIコンポーネント
- `src/data/`：型付きの社員・モードデータ
- `src/hooks/`：localStorageとReact状態の同期
- `src/types/`：社員、モード、保存状態の型定義
- `src/utils/`：進捗計算などの純粋関数
- `server/`：ローカル専用Express APIとOllama接続
- `assets/`：承認済みの背景・キャラクター素材
- `prototype/`：React化前の参照用試作

## 転職面接で説明できる技術的なポイント

### データ駆動のUI

5名のプロフィール、担当、会話と、5モードの時刻・状態・配置をTypeScriptのデータとして分離しました。人物情報をコンポーネントへ散在させず、追加や変更を局所化しています。

### 派生状態による進捗管理

全体進捗を独立して保存せず、5名の社員進捗の平均を毎回計算して四捨五入しています。二重管理による不整合を防ぐ設計です。初期値は `45 + 40 + 30 + 35 + 25 = 175` で、平均35%になります。

### 安全なlocalStorage復元

選択モードと進捗をブラウザに保存します。保存値が壊れている、範囲外である、項目が不足している場合も検証・補正し、アプリが起動できるようにしています。

### CSS中心の軽量アニメーション

外部アニメーションライブラリを使わず、CSS TransformとTransitionで人物を移動します。`prefers-reduced-motion`では反復アニメーションと補間を実質的に停止します。

### アクセシビリティとレスポンシブ対応

操作要素にはネイティブのbutton、選択状態には`aria-pressed`、進捗には`role="progressbar"`を使用しています。キーボードフォーカスを明示し、狭い画面では1カラムへ切り替えます。

### テスト可能な設計

進捗計算を純粋関数として単体テストし、社員選択、全モード、永続化、進捗更新をTesting Libraryで利用者視点からテストしています。
