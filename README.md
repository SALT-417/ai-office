# AI OFFICE

5人のアニメAI社員がカテゴリに応じて役割分担する、個人向けの汎用ローカルAIチームです。アプリ自体はAIエンジニア転職用のポートフォリオ作品ですが、入力する仕事は一般業務、AI学習、ソフトウェア開発、転職・キャリア、コンテンツ・SNSから選べます。画面はReact、TypeScript、Viteで構築し、ローカル実行時のみExpressとOllamaを使います。外部AI API、クラウドバックエンド、データベース、課金サービスは使用していません。

公開URL：[https://salt-417.github.io/ai-office/](https://salt-417.github.io/ai-office/)

## 主な機能

- 業務・移動・休憩・会議・夜間の5モード
- 承認済みの背景と5名のキャラクターによるオフィス表示
- 社員選択による担当、現在のタスク、進捗、会話の表示
- 社員進捗の平均を四捨五入した全体進捗
- モード、選択社員、社員進捗のlocalStorage保存
- デスクトップとモバイルに対応したレスポンシブ表示
- キーボード操作、フォーカス表示、ARIA、モーション軽減対応
- 画面からレンへ依頼し、担当者と最初の作業を確認できるローカルAI機能
- 5つの業務カテゴリと、カテゴリ別の担当者判定・プロンプト・固定サンプル
- 各カテゴリ3件の依頼テンプレートと、送信前に編集できる入力支援
- よく使う依頼文をカテゴリ別に保存・再利用できる自分用テンプレート
- 専門社員の成果物履歴と、人による承認・差し戻しフロー
- GitHub Pagesでも設計と操作を確認できる、API非通信の公開サンプルモード

## Windowsでの起動手順

### 1. Node.jsを準備する

[Node.js公式サイト](https://nodejs.org/)からLTS版をインストールします。インストール後にPowerShellを開き、次を入力してバージョン番号が表示されることを確認してください。

```powershell
node --version
npm --version
```

### 2. プロジェクトフォルダを開く

エクスプローラーでこのフォルダを開き、アドレスバーに `powershell` と入力してEnterキーを押します。

### 3. パッケージをインストールして起動する

```powershell
npm install
npm run dev
```

PowerShellに表示された `http://localhost:5173/` をブラウザで開きます。終了するときはPowerShellで `Ctrl + C` を押します。

## ローカルAI機能

### 起動条件

ローカルAI APIを利用するには、Node.jsに加えて[Ollama](https://ollama.com/)が必要です。Ollamaをインストールして起動し、初期モデルをPowerShellで取得してください。

```powershell
ollama pull qwen2.5:3b
```

その後、プロジェクトフォルダで次を実行します。`npm run dev`はViteとローカルExpress APIを同時に起動します。

```powershell
npm ci
npm run dev
```

- Web画面：`http://localhost:5173/ai-office/`
- 計画API：`http://127.0.0.1:8787/api/manager`
- テキスト成果物API：`http://127.0.0.1:8787/api/work`
- Ollama API：`http://127.0.0.1:11434/api/chat`

画面下部の「AIへ仕事を依頼」で業務カテゴリを選び、内容を入力して「レンに依頼する」を選択します。各カテゴリには3件の依頼テンプレートがあり、選ぶと自然な日本語の依頼文が入力欄へ入ります。自動送信はされないため、内容を確認・編集してから明示的に送信できます。計画が表示されたら「担当社員に実行してもらう」を選ぶと、該当する専門社員が順番にテキスト成果物を作ります。

入力中の依頼文は「自分用テンプレートとして保存」から現在のカテゴリへ保存できます。タイトルは任意で、未入力の場合は依頼文の先頭から自動作成します。保存後は再利用、名前変更、確認ダイアログ付き削除が可能です。保存先はこのブラウザの`ai-office-custom-request-templates-v1`だけで、外部サーバーには保存しません。全体30件、1カテゴリ10件までです。秘密情報や個人情報は保存しないでください。

### 5カテゴリと役割分担

5名の基本役割と画像は変えず、選択カテゴリに応じた担当内容をサーバーから固定します。

| カテゴリ | レン | ミオ | ソウ | ユナ | アキ |
| --- | --- | --- | --- | --- | --- |
| 一般業務 | 目的・優先順位・進行 | 利用者視点・情報・調査 | 技術・自動化・手順 | 文章・資料・伝え方 | 確認・リスク・品質 |
| AI学習 | 目標・期間・優先順位 | キャリア接続・テーマ | 解説・演習・実装課題 | 教材・要約・ノート | 理解度・復習・達成条件 |
| ソフトウェア開発 | 要件・優先順位・節目 | 利用者・業務価値 | 設計・実装・API | UI/UX・文言・情報設計 | テスト・安全性・アクセシビリティ |
| 転職・キャリア | 活動計画・進捗 | 求人・企業・応募・面接 | 技術経験・作品実装 | 自己PR・作品説明 | 整合・誤記・品質 |
| コンテンツ・SNS | 企画・投稿計画 | 視聴者・テーマ調査 | 制作支援・効率化 | 企画・構成・投稿文 | 事実・投稿前確認・安全性 |

AIの出力は提案として表示され、利用前に人が確認する前提です。この段階ではファイル変更、コマンド実行、Git操作、外部送信は行いません。

Express APIだけを起動する場合は次を使用します。

```powershell
npm run start:api
```

### API仕様

`POST /api/manager`へJSONを送信します。依頼内容は1〜2000文字です。`POST /api/work`も同じカテゴリを受け取ります。

```json
{
  "category": "learning",
  "task": "7日間でReactの基礎を学ぶ計画を作ってください"
}
```

成功時はレンの返答を返します。

```json
{
  "manager": "レン",
  "category": "learning",
  "reply": "依頼内容を確認しました。担当者候補は…"
}
```

新しい画面は必ず`category`を送ります。古いクライアントが省略した場合は`general`として扱い、不正な値は400で拒否します。担当者と役割はクライアント値を信用せず、カテゴリと依頼文からサーバー側で決定します。専門成果物はレンを除く最大4名で、1名が失敗してもほかの結果を維持します。

モデルなどを変更する場合は、`.env.example`に記載された環境変数をPowerShellで設定してから起動します。APIキーや秘密情報は不要です。

```powershell
$env:OLLAMA_MODEL = "qwen2.5:3b"
$env:OLLAMA_TIMEOUT_MS = "30000"
$env:WORK_TIMEOUT_MS = "90000"
$env:ANALYSIS_TIMEOUT_MS = "60000"
npm run dev
```

### 読み取り専用プロジェクト分析

ローカル版の「プロジェクトを分析」では、「安全なファイル一覧を取得」を押し、目的、ソウまたはアキ、1〜8件の対象を明示的に選びます。「選択ファイルを確認」でファイル名と件数を確認した後だけ分析を開始できます。これはAI OFFICE自身のコードを根拠付きで調べる専用機能なので、一般の仕事カテゴリとは独立させ、React・Express・Ollamaなど既存プロジェクトの確定コンテキストを維持します。

- 対象：`src/`、`server/`、READMEと明示許可したルート設定ファイル
- 除外：`.env`、隠しファイル、symlink、`prototype/`、lockfile、画像、生成物、許可範囲外
- 上限：1ファイル20KB、合計60KB、最大8件、目的1000文字
- AI：ローカルOllamaのみ。外部AI APIへ送信しません
- 動作：読み取りとテキスト提案のみ。ファイル変更、コマンド実行、Git操作、外部送信は行いません

秘密鍵、APIキーらしい値、Bearerトークン、パスワード代入はOllamaへ渡す前に伏字へ置換します。ただし検出は完全ではないため、利用者自身が対象ファイルを確認し、秘密情報や個人情報を含むファイルを選ばないでください。ソース内のコメントやREADMEは命令ではなく分析データとして扱います。

結果は根拠の相対パス、行番号、改善案、完了条件、確認方法を含みます。ファイル全文やOSの絶対パスはブラウザへ返しません。Ollamaには選択pathを列挙したJSON Schemaを渡し、軽微なコードフェンス、severityの高・中・低、数値文字列のline、重複、配列上限だけを安全に正規化した後、件数・文字数・選択path・行番号をサーバー側で再検証します。構造が正しくても、汎用文だけ、目的と無関係、ファイル役割を説明しない、ほぼ同一のfindingsは決定論的な品質ルールで拒否します。不正時の再生成はfieldと理由だけを伝えて最大1回行い、なお採用できない場合は選択ファイル別の「確認候補」を行番号なしで表示します。分析履歴は既存作業履歴と分離した `ai-office-analysis-history-v1` に最大20件保存し、承認、差し戻し、メモ、コピー、1件削除ができます。承認しても自動実行されません。

### 作業履歴と承認

専門社員の実行が完了すると、依頼、レンの計画、社員別成果物をブラウザのlocalStorageへ最大20件保存します。「作業履歴」から詳細を選び、任意の確認メモとともに承認または差し戻しを記録できます。履歴の成果物はクリップボードへコピーでき、同じ依頼を入力欄へ戻して内容を確認してから再依頼できます。

- 保存キー：`ai-office-work-history-v1`
- 保存形式：`version: 2`を持つバージョン付きJSON（カテゴリを含む）
- 保存場所：現在使用しているブラウザのみ
- 外部送信：なし
- 承認後の自動実行：なし

履歴を1件またはすべて削除する場合は、画面内の確認ダイアログで対象を確認します。削除対象は作業履歴だけで、オフィスのモード、社員選択、進捗は削除しません。秘密情報や個人情報は依頼・確認メモへ入力しないでください。

既存の`version: 1`履歴は削除せず、読み込み時にカテゴリ未指定の旧履歴を`general`として安全に移行します。現在のカテゴリは別キー`ai-office-work-category-v1`へ保存し、壊れたJSON・古い形式・不正値は`general`へ復旧します。他のlocalStorageキーは変更しません。

### GitHub Pages版について

[GitHub Pages版](https://salt-417.github.io/ai-office/)は明示的な `public-demo` モードです。ExpressやOllamaへ通信せず、5カテゴリそれぞれの固定テンプレートと、自分用テンプレートの保存・再利用・名前変更・削除、「サンプル計画」「サンプル成果物」と従来の「サンプル分析」を確認できます。自分用テンプレートは使用中ブラウザのlocalStorageだけへ保存されます。依頼文は入力・編集できますがAI送信ボタンは無効です。各サンプル結果には、現在AIが生成したものではないことを明記しています。

ローカルの `npm run dev` は `local-ai` モードで、固定または自分用テンプレートから選んだ依頼も編集後の文章も、カテゴリ付きでExpressとOllamaへ送信できます。テンプレートの保存操作自体はAPIを使わず、ブラウザ内だけで完結します。ViteからExpressへ `/api` をプロキシし、Ollamaによる実際の生成を利用します。実行モードは `VITE_APP_RUNTIME_MODE` で明示し、不正な値はAPI通信をしない `public-demo` へ安全に倒します。

### アーキテクチャと安全設計

`React 19 + TypeScript + Vite 7` のフロントエンド、ローカル専用の `Node.js + Express + TypeScript` API、`Ollama qwen2.5:3b` で構成します。マネージャー計画、専門成果物、読み取り専用分析は構造化レスポンスとしてサーバーで再検証します。担当者の固定、入力上限、失敗分離、タイムアウト、AbortControllerによるキャンセル、StrictMode対策を実装しています。

コード分析は選択された許可ファイルだけを読み、pathとsymlink、秘密らしい値、ファイル内プロンプトインジェクション、根拠path・line、内容品質を検証します。AI社員はファイル変更、コマンド実行、Git操作、外部送信を行いません。成果物と分析は人が確認・承認しますが、承認も自動実行を意味しません。

自動テストは、5モードと社員選択、進捗・localStorage、API成功・失敗・タイムアウト・キャンセル、StrictMode、履歴・承認、分析の境界値と安全検証、公開版のAPI非通信と固定サンプル分離を対象にしています。サンプルデータは機能説明用の固定例であり、実行実績や分析済み事実を示すものではありません。

## GitHub Pagesへのデプロイ

`main`ブランチへpushすると、`.github/workflows/deploy.yml`が自動実行されます。ワークフローは次の順序で処理し、すべて成功した場合だけGitHub Pagesへ公開します。

1. Node.jsのLTS版を準備
2. `npm ci`でロックファイルどおりに依存関係をインストール
3. 型チェック、ESLint、自動テストを実行
4. `/ai-office/`をベースパスとして本番ビルド
5. `dist`をGitHub Pages artifactとしてアップロード
6. 公式の`actions/deploy-pages`で公開

初回公開時は、GitHub上のリポジトリで **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定してください。その後、`main`へのpushまたはActions画面の手動実行で公開されます。アクセストークンやAPIキーの追加は不要です。

build stepでは `VITE_APP_RUNTIME_MODE=public-demo` を明示し、公開artifactにはViteの `dist` だけを含めます。ローカルAPIサーバーや秘密情報は配信されません。

## プロジェクト構成

- `src/components/`：役割ごとに分割したUIコンポーネント
- `src/data/`：型付きの社員・モードデータ
- `src/data/publicDemo.ts`：API通信や履歴保存を行わない公開用固定サンプル
- `src/data/requestTemplates.ts`：5カテゴリ各3件の型付き依頼テンプレート
- `src/utils/customRequestTemplateStorage.ts`：自分用テンプレートの検証・上限・localStorage永続化
- `shared/workCategories.ts`：画面とローカルAPIで共有するカテゴリ・カテゴリ別担当定義
- `src/hooks/`：localStorageとReact状態の同期
- `src/types/`：社員、モード、保存状態の型定義
- `src/utils/`：進捗計算などの純粋関数
- `server/`：ローカル専用Express APIとOllama接続
- `assets/`：承認済みの背景・キャラクター素材
- `prototype/`：React化前の参照用試作

## 転職面接で説明できる技術的なポイント

### データ駆動のUI

5名のプロフィール、担当、会話と、5モードの時刻・状態・配置をTypeScriptのデータとして分離しました。人物情報をコンポーネントへ散在させず、追加や変更を局所化しています。

### 派生状態による進捗管理

全体進捗を独立して保存せず、5名の社員進捗の平均を毎回計算して四捨五入しています。二重管理による不整合を防ぐ設計です。初期値は `45 + 40 + 30 + 35 + 25 = 175` で、平均35%になります。

### 安全なlocalStorage復元

選択モードと進捗をブラウザに保存します。保存値が壊れている、範囲外である、項目が不足している場合も検証・補正し、アプリが起動できるようにしています。

### CSS中心の軽量アニメーション

外部アニメーションライブラリを使わず、CSS TransformとTransitionで人物を移動します。`prefers-reduced-motion`では反復アニメーションと補間を実質的に停止します。

### アクセシビリティとレスポンシブ対応

操作要素にはネイティブのbutton、選択状態には`aria-pressed`、進捗には`role="progressbar"`を使用しています。キーボードフォーカスを明示し、狭い画面では1カラムへ切り替えます。

### テスト可能な設計

進捗計算を純粋関数として単体テストし、社員選択、全モード、永続化、進捗更新をTesting Libraryで利用者視点からテストしています。

### 実行環境を安全側へ分ける判断

hostname推測ではなくbuild時の明示設定で `local-ai` と `public-demo` を分け、不正値は非通信モードへ倒します。UIだけでなく通信hookにもガードを置くことで、静的ホスティングから存在しないAPIを呼ばない設計です。採用担当者には固定サンプルで操作を伝えつつ、実結果・実履歴との誤認を防ぎます。

### カテゴリと依頼文を組み合わせる担当者判定

カテゴリだけで全員を固定せず、カテゴリ別キーワードと依頼文の両方から必要な社員をコードで選びます。複数分野や計画依頼ではレンを調整役に加え、該当者がいない場合だけカテゴリ別の既定担当へ安全に倒します。モデルには選定済み社員とカテゴリ別役割を渡し、別カテゴリや転職用途へ勝手に置き換わることを防ぎます。
